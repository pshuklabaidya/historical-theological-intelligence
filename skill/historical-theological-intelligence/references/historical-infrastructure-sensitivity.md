# Historical infrastructure and sensitivity

Use this reference for requested access, ownership/use, transmission-route, or historical what-if questions. Ordinary translation runs neither operation. The existing HRG and source-transmission forensics adjudicate dependence and immediate-source identity. Network evidence informs their access/plausibility conditions.

ACCESSIBLE != USED. POSSESSED != DEPENDENT. SAME NETWORK != INTELLECTUAL TRANSMISSION.

## Current network record

Save `<TASK_DIR>/hti-historical-infrastructure.json`. Import `Infrastructure` and `revalidate` from `hti_core.historical_infrastructure`, with the Skill scripts directory on the Python path. `revalidate(document)` is an explicit reviewed evidence update; completion never refreshes a stale record automatically.

The exact document fields are `schema_version: hti-historical-infrastructure-1`, `evidence`, `entities`, `records`, `paths`, and `bindings`. Lists may be empty except the evidence datasets required by the native substrate. `evidence` is the existing Cartography document, with its licensed current datasets/dossiers and optional maps/comparisons. Reuse that document, identities, source registries and uncertainty requests, rather than rebuilding evidence from prose or from a persisted result. Its complete public schema is documented in [cartography](cartography.md).

An entity has `id`, `kind`, `name`, `dataset_id`, and `evidence`. Kinds: ANCHOR_AUTHOR, SOURCE_WORK, INTERMEDIARY, PERSON, INSTITUTION, BOOK, PRINTER. Each evidence reference has `dataset_id` and the native integrity `ref` with representation/span IDs and current snapshots. ANCHOR_AUTHOR must match the licensed dataset author; SOURCE_WORK must match its independently licensed work. Other identities are source-bound scholarly identifications. No persisted entity establishes its own identity.

Every network record has exactly:

- `id`, `anchor_dataset_id`, `anchor_proposition_ids`;
- `source_entity_id`, `target_entity_id`, `relation_type`;
- `claim_level` (WORK, EDITION, EXEMPLAR), `geographic_scope`, `institutional_scope`;
- `temporal`, `evidence`, `counterevidence`, `alternatives`, `confidence`, `rationale`;
- `status` (CURRENT or REVALIDATION_REQUIRED), `snapshot` (SHA-256 of the selected current basis).

Relation types: TEACHER_STUDENT, UNIVERSITY_PRESENCE, LIBRARY_OWNERSHIP, BOOK_POSSESSION, PRINT_DISTRIBUTION, CORRESPONDENCE, TRANSLATION_NETWORK, SYNODAL_ECCLESIAL_CONTACT. These describe documented relations, not intellectual transmission edges. Scope follows the actual licensed identity level. Same-author wrong-work evidence is never a current-work fact.

Each evidence item has `id`, `kind`, `inspection`, `verification`, `source_refs`, `assertion`, `rationale`. Kinds: NETWORK_DOCUMENTATION, ACCESS_DOCUMENTATION, POSSESSION_DOCUMENTATION, USE_DOCUMENTATION, CHRONOLOGY, COUNTEREVIDENCE. Inspection: PRIMARY_PASSAGE, PRIMARY_METADATA, SECONDARY_REPORT, OCR_LOCATOR, UNINSPECTED. Verification: VERIFIED, PROVISIONAL, UNRESOLVED, CONTRADICTED. Record the proposition the document actually supports; an inspected catalog entry supplies only its recorded metadata, never the contents of an uninspected letter or book. Actual-use evidence requires inspected primary contents; source-layer permission is independently checked. Translation/OCR/secondary leads remain useful but cannot masquerade as inspected original documentation. Record counterevidence and live alternatives rather than forcing a single route. No probability field is permitted.

`temporal` has `constraints` and `rationale`. Each constraint has `id`, `kind`, `state`, `earliest`, `latest`, `evidence`, `rationale`. Kinds: SOURCE, RELATION, INSTITUTION, POSSESSION, PRINT_DISTRIBUTION, CORRESPONDENCE, TRANSLATION. States: SECURE, UNCERTAIN, UNAVAILABLE. Unavailable bounds are null. Include the relevant institutional/print/possession/translation intervals, not merely work dates. A SOURCE_WORK constraint must match its native date. Anchor date comes from the independently licensed native dataset. Impossible chronology defeats access; unresolved bounds constrain it. Feasibility never proves reading or dependence.

A Stage 8 historical explanation may consume the returned native access assessment directly: its provenance `origin: source_bound_network` and `locator: <network record ID>` explicitly bind that access fact. The dataset and anchor propositions must match. Changed access requires canonical explanation revalidation; an unbound explanation gains no inferred network dependency. Stage 9 historical references and Stage 10 cartographic object references follow their existing native dependencies without merging domains.

`paths` have `id`, `anchor_dataset_id`, `anchor_proposition_ids`, `record_ids`, `rationale`, `status`, `snapshot`. Ordered records must form a finite noncycling path ending at the actual licensed anchor author. Every edge retains its own access and chronology. Multiple possible paths may remain live. `bindings` have `id`, `anchor_dataset_id`, `anchor_proposition_ids`, `historical_edge_id`, `path_ids`, `rationale`, `status`, `snapshot`. A binding references an existing native HRG edge (active for a supported relation), its true source/target dossiers, and discriminating correspondence for dependence. It creates no HRG edge. A stale or infeasible access basis requires re-adjudication; an active native edge cannot remain current through a binding whose declared essential access paths are all impossible or unresolved. Correct the canonical native edge state before refreshing that binding; use the ordinary canonical HRG revision route rather than treating the old edge as refreshed.

`Infrastructure(document).current_outputs()` returns exact rendered network/path/binding outputs. Bind each to an evidence-checkpoint claim with `claim_type: historical_infrastructure`, `infrastructure_id` (the returned output key), and `infrastructure_sha256` (SHA-256 of that rendered UTF-8 output). Include it in the normal response plan. The governed completion gate requires all current outputs visible, work-bound to the actual task source, and staged for the current publication.

## Hypothetical sensitivity

Save `<TASK_DIR>/hti-historical-sensitivity.json`. Import `prepare_scenario` and `Sensitivity` from `hti_core.historical_sensitivity`. The exact document fields are `schema_version: hti-historical-sensitivity-1`, `infrastructure` (the exact current canonical network document), `novelty` (the matching native Novelty document or null), and `scenario`.

The scenario has `id`, `work_id`, `interventions`, `targets`, `rationale`, `snapshot`. Every typed reference has `domain`, `dataset_id`, `id`, `sub_id`. Domains: PROPOSITION, REPRESENTATION, PRG_RELATION, HISTORICAL_EDGE, EXPLANATION, MAP, NOVELTY, NETWORK_RECORD, ACCESS_PATH, HISTORICAL_BINDING, ENTITY. MAP uses its map ID and claim `sub_id`; other sub-IDs are null. All references must exist in the already constructed source/native records. Target conclusions belong to the current licensed work; antecedent source interventions may reference independently licensed comparison datasets only through their actual dependencies.

Each intervention has `id`, `target`, `operation`, `related_target`, `rationale`. Operations: REMOVE, DOWNGRADE, INACCESSIBLE, TRANSLATION_CREATED, COLLAPSE_DERIVATIVE, CHRONOLOGY_DOWNGRADE, ATTRIBUTION_DOWNGRADE. The allowed intervention targets are existing propositions, representations, PRG relations, HRG edges, network records and entities. Access/chronology operations apply to network records/entities. Translation-created applies to representations. Attribution downgrade applies to propositions/representations/historical edges. Derivative collapse requires a different existing representation as `related_target`; other related targets are null. It collapses source roots only within the isolated native scenario view.

Call `prepare_scenario(document)` after explicitly defining the hypothetical intervention, then `Sensitivity(document).results()` and `.render()`. The preparation binds the scenario to the current canonical evidence; a prior result cannot satisfy changed inputs. Native dependency uncertainty computes proposition paths and genuine independent support. Consumer, map, novelty and historical/network references preserve actual selected dependencies; affected macro judgments conservatively require revalidation where native evidence supplies no determinate replacement. An independent unrelated conclusion survives. For network records, surviving documentary items must retain their inspected source basis and the evidence role actually required by each access/possession/use assertion. Losing one corroborator leaves independently supported facts intact; losing the sole access document qualifies access without erasing separately documented contact. Derivative discovery collapses original roots within the scenario rather than manufacturing historical falsity. No new relationship is invented to exercise sensitivity.

Outcomes distinguish REMAINS_SECURE, REMAINS_AS_BASELINE, WEAKENS, COLLAPSES, RELATION_TYPE_CHANGES, and UNRESOLVED. Collapse means loss of support under the stated scenario, not historical falsity. A relation downgrade may leave the relation unresolved rather than inventing conceptual affinity. Audit results retain affected intervention IDs, typed dependency paths, native uncertainty paths and before/after states. No numerical confidence is produced.

Bind the single exact rendered scenario to a checkpoint claim with `claim_type: historical_sensitivity`, `sensitivity_id` (scenario ID), and `sensitivity_sha256`. Stage both network and scenario inputs for the current publication. Complete with the existing commentary or Scholar View helper, and return only the exact helper terminal. Substantive follow-up requires fresh publication state; a prior receipt never satisfies current work.

A sensitivity run changes no canonical evidence. Hypothetical results are analytical and cannot establish historical facts or be supplied as positive evidence. A later actual ownership correction, redating, attribution correction or derivative discovery uses the ordinary source/HRG revision and invalidation machinery. Revalidate dependent network records, maps and novelty claims according to their real basis. A previous scenario replaces none of these corrections.

## Retained research state

Use the existing work-bound research JSONL ledger: `research_state.append_historical(directory, network_document)` or `append_historical(directory, scenario_document, sensitivity=True)`. Full validated snapshots and hashes remain inspectable. The index labels retained results as requiring current evidence validation; scenarios remain hypothetical. Persistence supplies no evidence, identity, automatic currentness or new specialization registration. Requested Stage 12 onboarding uses [its separate workflow](specialization-onboarding.md).
