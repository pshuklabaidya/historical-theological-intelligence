# Core Workflow

Before step 1, retain the exact owned task and select its current publication: use `task_state.py begin-publication --state-dir "$HTI_STATE_DIR" --route commentary --request "EXACT CURRENT SUBSTANTIVE REQUEST"` for the first substantive response or any substantive linked follow-up (use `--route scholar` for Scholar View). Reuse the same task/research state after prior completion; open a new publication, not a new task. Resume unfinished current work with `resume-publication`. Acknowledgements and administrative status/history do not open scholarly publications.

1. Inventory the supplied files and keep originals unchanged.
2. Inspect page structure, legibility, layout, marginalia, signatures, catchwords, and damage from the supplied image. State orientation only when evidence supports it. Read [image processing](image-processing.md) before any derivative. A finite region plan answers each consequential evidentiary question; multiple needed regions are permitted. Every view starts from original pixels and retains provenance. Close questions when resolved or unresolved after their planned effort; reuse views rather than recropping. Keep unresolved source forms uncertain.
3. Transcribe internally from the supplied page, preserving uncertainty before consulting other witnesses.
4. Translate the whole readable passage. An unidentified page is fully translatable.
5. Identify the work or edition only to the state justified by evidence. Style, theology, genre, remembered wording, and similar leads may suggest a private search hypothesis but do not establish identity. Record every named current-work hypothesis actually considered in `identity_hypotheses`, with useful aliases, `user_visible: false`, and `admissible_as_identity_evidence: false` unless admissible evidence later supports it.
6. Consult registered witnesses when needed for consequential resolution or requested comparison, never replacement of the supplied page.
7. Verify only the sources and notes relevant to the user's request. Finish the readable translation before refining optional notes. Optional notes must not consume the tool budget needed to reach structured completion; omit or simplify them when they trigger disproportionate inspection or annotation work.
8. For ordinary translation and other canonical structured routes, write the evidence checkpoint to `<TASK_DIR>/evidence-checkpoint.json`, write the structured response plan to `<TASK_DIR>/final-response-plan.json`, and run `python3 scripts/complete_commentary_task.py --state-dir "$HTI_STATE_DIR"` from the installed Skill root. For Scholar View, use the compact production interface instead: fill `<TASK_DIR>/scholar-view-task.json` from `resources/templates/scholar-view-task.json`, for an actual image let `--prepare-long-s` derive deterministic s/f state and report only cross-layer cases needing visual adjudication, then run `python3 scripts/complete_scholar_view_task.py --state-dir "$HTI_STATE_DIR"`. That adapter deterministically expands the compact task into the same canonical checkpoint and response plan in the selected task directory, then delegates to the canonical evidence audit and renderer. Do not rebuild those canonical files by hand during routine Scholar View execution. After preparation and all research, run `python3 scripts/task_state.py stage-publication --state-dir "$HTI_STATE_DIR"` to bind the current request/route to the current canonical or compact inputs. Any later scholarly resource read/search removes draft readiness and requires current restaging. Both helpers delegate their validated renderer output to the same final publication operation. It saves `validated-response.md` and `completion-receipt.json`, then emits exact UTF-8 response bytes once. Complete all other tool work first. Never redirect the publishing helper or use it as a captured test. All research, source inspection, corrections, preparation and progress updates precede the committed response. Design R selects transport from exact UTF-8 bytes: DIRECT_STDOUT at or below 24,000 bytes emits the committed answer and stops with no later tool; READ_COMMITTED_FILE above that ceiling emits a short current-publication path/hash/byte-count stub, followed only by one exact Read with allow_large=true, exact relay and stop. No other post-stub tool, narration, editing or new publication is permitted. Later truthful recovery preserves the same commit and repeats its direct payload or bound stub, never scholarship. An error has no provisional stdout; correct the structured inputs and retry the same helper. The transport ceiling never limits requested scholarly content. Before success, an interruption response is exactly `Structured completion is unfinished. Continue to resume from the preserved checkpoint.`

For multi-page input, reconstruct order from explicit pagination or foliation, signatures, text continuity, and catchwords. Treat a catchword as sequence evidence, not by itself as recto/verso evidence.

If a page is damaged, give the readable translation and mark lacunae. Physical visibility controls observational transcription: letters hidden by masking, loss, cropping, binding, damage, or opaque obstruction remain `[obscured]`, `[illegible]`, or a measured lacuna in both diplomatic and normalized layers. Record such a region in `legibility_regions` as `PAGE_OBSCURED` or `PAGE_LOST`. A plausible completion belongs only in a separate `CONJECTURE` or `WITNESS_RECONSTRUCTION` layer with `relationship: RECONSTRUCTS`; it never becomes a visible reading. For final transcription, carry the same state into `output.transcription_spans`.

## Scholar View from supplied text

Keep the scholar route for a non-image request. Register the actual primary text in source-integrity.json and set compact source_anchor to {"representation_id":"ACTUAL-ID","evidence_id":"PRIMARY-ID"}; bind that evidence ID on its representation. The adapter supplies that primary evidence item, so do not duplicate it in task.evidence. Keep locus.page_id and image_sha256 null. Set sections.supplied_text to the exact registered content; it displays in Notes, with the actual representation layer and unavailable image apparatus disclosed through current governed assertions. Do not label normalized supplied text photographed diplomatic Latin. Non-image tasks omit diplomatic_latin and rare_book_notes; normalized_latin is permitted only for an actual NORMALIZED_TRANSCRIPTION anchor. Required non-image sections are supplied_text, textual_uncertainties, theological_loci and exegetical_method, with the same witness status discipline.

The selected SCHOLARLY_TRANSLATE outcome is PARTIAL with actual current results, a visible specific reason and limitations for unavailable image-dependent apparatus. COMPLETED would falsely complete that apparatus; total BLOCKED would discard useful work. Preserve the full translation, gaps and uncertainty. ORIGINAL_TEXT retains its own permissions; RAW_OCR and derivatives remain provisional unless genuinely reviewed; historical/modern translations cannot establish underlying wording or glyphs. Primary text or its derivative is not an independent comparator. Explicitly analyzed Greek/Hebrew from supplied text uses source_layer supplied_text and its primary reading evidence, never a false image check.

For actual image tasks retain exact locus/hash and E-SUPPLIED-PAGE binding, diplomatic and normalized separation, prepare-long-s, real image attestation, high-risk gates and finite registered inspection. For non-image tasks prepare-long-s reports inapplicability without manufacturing a checklist; structured completion remains mandatory and all core source permissions still apply.
