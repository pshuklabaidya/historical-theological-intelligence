# Scholar output annex

## Scholar View compact production interface

Routine Scholar View uses one compact task file rather than hand-authoring the canonical checkpoint and response plan.

1. Copy `resources/templates/scholar-view-task.json` to `<TASK_DIR>/scholar-view-task.json`.
2. Complete the translation, the required Scholar View sections, witness status, evidence, identity state, named-entity registry, and the dedicated long-s review attestation in that file.
3. Run `python3 scripts/complete_scholar_view_task.py --state-dir "$HTI_STATE_DIR"` from the installed Skill root.
4. Finish all other tool work before the completion call. Both helpers use the shared final publication operation to save the exact response and input-bound receipt before emitting the selected transport once. Never redirect or capture the publishing helper as a test. All research, source inspection, corrections, preparation and progress updates precede the committed response. Design R selects transport from exact UTF-8 bytes: DIRECT_STDOUT at or below 24,000 bytes emits the committed answer and stops with no later tool; READ_COMMITTED_FILE above that ceiling emits a short current-publication path/hash/byte-count stub, followed only by one exact Read with allow_large=true, exact relay and stop. No other post-stub tool, narration, editing or new publication is permitted. Later truthful recovery preserves the same commit and repeats its direct payload or bound stub, never scholarship. The adapter also writes the canonical checkpoint and response plan to the selected task directory before finalization, so the same evidence audit, identity renderer, long-s gate, and final pre-output audit still govern the response.

The compact task deliberately keeps routine authoring shallow:

- `translation` is the complete English page translation.
- `sections` maps fixed Scholar View section kinds to either one string or a list of paragraph strings. For image tasks, required routine sections are `rare_book_notes`, `diplomatic_latin`, `normalized_latin`, `textual_uncertainties`, `theological_loci`, and `exegetical_method`; `witness_comparison` is supplied or generated from the explicit witness status. `source_notes`, `notes`, `citation`, and `research` remain optional.
- `witness_comparison.status` is `completed`, `unavailable`, or `declined`. `completed` requires evidence IDs for independently inspected `other_witness` or `historical_translation` evidence with `passage_inspected: true`. `unavailable` or `declined` requires a concise limitation. A page-internal variant report cannot satisfy this field.
- `identity.state` uses the normal identity-state vocabulary. For `WORK_ESTABLISHED` or higher, `identity.name` and admissible discriminating `identity.evidence_ids` are required. The adapter creates only the work-identity claim; an `EDITION_ESTABLISHED` or `EXEMPLAR_ESTABLISHED` task must also supply its canonical higher-level claim(s) in `claims` and select them.
- `evidence` uses the existing canonical evidence-item shape. For an actual supplied-image anchor, the adapter supplies its page observation as `E-SUPPLIED-PAGE`; external identity and comparator evidence still require their own provenance-bearing entries.
- `_interface` in the template exposes the complete compact contract: evidence classes, the narrower promoted-work identity evidence classes, identity requirements, legal entity role/scope pairs, page-name/page-token applicability, witness statuses, analytical-claim type-specific fields and marker semantics, foreign-token nested fields, diacritic-only alternate forms, evidence roles, long-s ownership, quote handling, selected-claim ownership, examples, and accepted enums. `--show-interface` prints the same contract. Implementation-source inspection is not part of ordinary authoring.
- Use literal UTF-8 for scholarly text. The adapter diagnoses mixed Latin/Cyrillic tokens that commonly result from mistaken codepoint entry and never silently rewrites an ambiguous character.
- `foreign_language_tokens` separates `reading_evidence_ids` from `gloss_evidence_ids`. Diacritic-only alternatives with the same underlying letters may be listed in `alternate_forms` under one token record; a different letter sequence is not an alias and fails closed. Supplied-page form/glyph claims require `E-SUPPLIED-PAGE` plus image checking; translations may support gloss meaning but cannot establish a supplied-page glyph. A gloss must be explicitly checked against its token. Non-secure readings remain non-secure, and the adapter appends a structured non-secure-status summary to Textual uncertainties.
- `analytical_claims` retains its high-risk externally checkable fields, but every substantive assertion also needs the common publication contract - textual or witness readings, source attributions, historical referents, page-supported named identifications, page-feature functions, and foreign-token glosses. `{{claim:CLAIM-ID}}` expands to the full claim text, so use it as the claim itself rather than as a citation after duplicate prose. Registered entity markers may occur inside claim text and are resolved before validation. Supported claims require evidence; the renderer adds inference/unresolved labels after named-referent validation.
- `entities` registers non-current historical persons, works, institutions, and comparators once. Registered displays and possessives are typed automatically; `{{entity:ENTITY-ID}}` remains available for ambiguous occurrences. A visible token does not automatically license a specific historical referent. When the display differs from the visible page form, record the visible token and explicit identification status/evidence. Do not use an entity marker to repeat the current work's own identity outside renderer-owned Identification.
- `diplomatic_latin` and `normalized_latin` are converted to typed page-text segments tied to the supplied page. This prevents Latin capitalization or historical names inside the transcription from being misread as free analytical identity claims.
- Final Scholar View completion runs an aggregate preflight before canonical construction. Independent current blockers are reported together where dependencies permit; fix that batch before rerunning.
- `selected_claim_ids` is identity-selection state, not analytical-claim bookkeeping. Leave it empty for ordinary WORK_ESTABLISHED Scholar View unless an explicit higher identity claim requires selection.
- In analytical sections, quotation marks are reserved for literal supplied-page wording. Write English glosses/paraphrases without quotation marks unless carried by a licensed analytical claim. Explicit rare-book function language belongs in a typed `feature_function` analytical claim.
- Preserve visible diplomatic abbreviation/suspension marks; Latin Extended and combining-mark forms are valid input to the alignment helper and must not be silently expanded for validator convenience. After drafting both `diplomatic_latin` and `normalized_latin`, run `python3 scripts/complete_scholar_view_task.py --prepare-long-s --state-dir "$HTI_STATE_DIR"`. The helper owns the checklist mechanics and pre-resolves ordinary cross-layer-consistent s/f tokens. Review only items reported as `manual_review_required`, correct the transcription or normalization itself, and rerun until the count is zero. Do not hand-edit token IDs, ordering, or resolution categories. Final completion automatically regenerates deterministic state and fails closed on any new cross-layer s/f mismatch. `long_s_review.reviewed_against_supplied_image` may be set to `true` only after the reported visual-review cases are settled.

If the adapter reports a compact-task error, fix the compact file and rerun the same command. The template and diagnostics expose the normal schema, enum values, evidence categories, and identity discriminators. Register a genuine named referent once in `entities`; repeated ordinary and possessive occurrences need no repeated entity registration. Routine Scholar View should not require inspecting implementation modules merely to discover JSON shape.


## Scholar View from supplied text

Keep the scholar route for a non-image request. Register the actual primary text in source-integrity.json and set compact source_anchor to {"representation_id":"ACTUAL-ID","evidence_id":"PRIMARY-ID"}; bind that evidence ID on its representation. The adapter supplies that primary evidence item, so do not duplicate it in task.evidence. Keep locus.page_id and image_sha256 null. Set sections.supplied_text to the exact registered content; it displays in Notes, with the actual representation layer and unavailable image apparatus disclosed through current governed assertions. Do not label normalized supplied text photographed diplomatic Latin. Non-image tasks omit diplomatic_latin and rare_book_notes; normalized_latin is permitted only for an actual NORMALIZED_TRANSCRIPTION anchor. Required non-image sections are supplied_text, textual_uncertainties, theological_loci and exegetical_method, with the same witness status discipline.

The selected SCHOLARLY_TRANSLATE outcome is PARTIAL with actual current results, a visible specific reason and limitations for unavailable image-dependent apparatus. COMPLETED would falsely complete that apparatus; total BLOCKED would discard useful work. Preserve the full translation, gaps and uncertainty. ORIGINAL_TEXT retains its own permissions; RAW_OCR and derivatives remain provisional unless genuinely reviewed; historical/modern translations cannot establish underlying wording or glyphs. Primary text or its derivative is not an independent comparator. Explicitly analyzed Greek/Hebrew from supplied text uses source_layer supplied_text and its primary reading evidence, never a false image check.

For actual image tasks retain exact locus/hash and E-SUPPLIED-PAGE binding, diplomatic and normalized separation, prepare-long-s, real image attestation, high-risk gates and finite registered inspection. For non-image tasks prepare-long-s reports inapplicability without manufacturing a checklist; structured completion remains mandatory and all core source permissions still apply.
